┌─────────────────────────────────────────────────────────────────────────────┐
│ ARCHITECTURE                                                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│
│  VERTICAL SLICE ARCHITECTURE (not traditional layered)
│  
│  src/
│  ├── domain/               ← Shared business logic
│  │   ├── entities/         ← User entity
│  │   └── value_objects/    ← Email, Password (validated types)
│  │
│  ├── features/             ← Feature slices (vertical)
│  │   └── auth/             ← Self-contained authentication
│  │       ├── handlers/     ← HTTP endpoints (sign-up, sign-in, refresh)
│  │       ├── services/     ← JWT, password services
│  │       └── models/       ← DTOs (request/response)
│  │
│  ├── infrastructure/       ← Technical plumbing
│  │   ├── database/         ← PostgreSQL pool
│  │   └── config/           ← Environment configuration
│  │
│  └── shared/               ← Cross-cutting concerns
│      ├── errors/           ← AppError (unified error handling)
│      └── kernel/           ← Result type, traits
│
│  KEY PRINCIPLE: Features depend on domain, never on each other
│
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ API ENDPOINTS                                                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│
│  POST /api/auth/sign-up
│  ├─ Creates new user account
│  ├─ Validates email (RFC 5322)
│  ├─ Validates password (8+ chars, mixed case, digit)
│  ├─ Hashes password with bcrypt
│  ├─ Returns JWT + Refresh Token pair
│  └─ Auto-signs user in
│
│  POST /api/auth/sign-in
│  ├─ Authenticates with email/password
│  ├─ Verifies password hash
│  ├─ Generates JWT access token (24h expiry)
│  ├─ Generates refresh token (7d expiry)
│  └─ Stores hashed refresh token
│
│  POST /api/auth/refresh
│  ├─ Validates refresh token
│  ├─ Verifies token hasn't been revoked
│  ├─ Issues new JWT + Refresh Token pair
│  ├─ Rotates tokens (old refresh invalidated)
│  └─ Used by clients to get new access tokens
│
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ KEY DESIGN DECISIONS                                                          │
├─────────────────────────────────────────────────────────────────────────────┤
│
│  1️⃣ User and Auth are SEPARATE features
│     ✅ Share domain model (User entity)
│     ✅ Keep implementations separate
│     ✅ Allows independent evolution
│     ❌ Avoids tight coupling
│
│  2️⃣ Value Objects for Domain Concepts
│     ✅ Email and Password are types, not strings
│     ✅ Validation happens once at creation
│     ✅ Self-documenting code
│     ✅ Type safety throughout
│
│  3️⃣ Result Type for Error Handling
│     ✅ All fallible operations return AppResult<T>
│     ✅ Errors auto-convert to HTTP responses
│     ✅ No need for manual error mapping
│     ✅ Type system ensures errors are handled
│
│  4️⃣ Refresh Token Rotation
│     ✅ Hash tokens before storage
│     ✅ Issue new token on refresh
│     ✅ Invalidate old token
│     ✅ Prevents token replay attacks
│
│  See COUPLING_ANALYSIS.md for detailed trade-off analysis

┌─────────────────────────────────────────────────────────────────────────────┐
│ EXTENDING THE PROJECT                                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│
│  To Add a New Feature:
│  
│  1. Create feature directory
│     mkdir -p src/features/[name]/{handlers,services,models}
│
│  2. Follow the patterns from auth feature
│     • handlers/ → HTTP endpoints
│     • services/ → Business logic
│     • models/ → Request/response DTOs
│
│  3. Share domain models
│     • Import from src/domain/
│     • Add new entities/value objects if needed
│
│  4. Keep features separate
│     • Never import from other features
│     • Depend on domain and infrastructure only
│
│  5. Add tests
│     • Tests in each module
│     • Run: cargo test
│
│  6. Update documentation
│     • Document endpoints in README.md
│     • Document architecture decisions
│
